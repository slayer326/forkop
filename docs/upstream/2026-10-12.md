# Selective upstream audit: 2026-10-12

## Compared revisions

- Fork baseline: `69cb310e` (release 1.0.48).
- Previous selective port: PR #29, Forkop 2.1 client fixes (2026-10-09).
- New upstream: [Screamshow/forkop-x](https://github.com/Screamshow/forkop-x)
  `d3d1650d` (2.3.0-canary.1).

The repositories share no Git history, so nothing is merged or cherry-picked;
each fix is re-applied by hand. Upstream commits after 2026-10-09 were checked
one at a time. Most were already in this fork or concern parts of upstream we
do not ship.

## Already present here

- Sniff-independent `hijack-dns` for the dedicated DNS inbounds (`becfbec9`).
- Bounded settling window for transient sing-box ownership conflicts and the
  LuCI status sampled after it (`9bb9146d`).
- Restart offered for an unhealthy runtime when Stop is available (`1d21060b`).

## Ported

**Own-traffic bypass with mwan3** (`456292de`). `mangle_output` returned
sing-box's own traffic only for an exact `meta mark == outbound`. mwan3 and
other policy routers add their own bits to the mark, so that traffic was
classified again and could loop back into TPROXY. The rule now tests only
our bit: `meta mark & outbound == outbound`. Forkop's marks are bit-disjoint,
which `validate_runtime_mark_ranges_context()` already enforces. The autotune
contract recognises a masked bypass (`P5_masked_bypass_first`), and
`tests/helpers/nft_real_check.js` now expects that form.

**sing-box working directory** (part of `75270858`). sing-box will not start
with a missing `-D` directory. Both managed-service script templates run
`mkdir -p "$working_directory"`, and `configure-service` creates the
configured `workdir` before it enables the service.

## Not ported

- **Prerouting interface guard and early return after common marking**
  (`7bfae995`, `c1becaa7`). This is a performance change. Here it would break
  autotune: `autotune/contract.uc` walks prerouting chains for WAN reply
  packets and does not treat a `return` as the end of the chain. Without the
  per-rule `iifname` matches, the mark statements would count as
  `reply_path_unsafe`. Upstream's matching `mangle_output` change also
  assumes provider queues come before the common tail; here the nfqueue
  provider appends after it. Port this only together with a reply walker that
  understands verdicts.
- **Transport-specific rule-set IPs** (rest of `75270858`). An IP rule limited
  to `network: tcp` is captured for UDP too. The fix needs per-section TCP
  `ip . port` sets, which this fork lacks; it only has the Discord UDP sets.
  Worth a separate change.
- **netstat wildcard family matching** (`75270858`). This would stop treating
  a dual-stack `::` listener as occupying the IPv4 port, which is wrong on
  Linux without `IPV6_V6ONLY`.
- **dnsmasq DHCP helper selection** (`36655912`), **list hot reload**
  (`c0aa06b0`) and **rollback staging** (`d3d1650d`) fix upstream modules
  (`dns/reload.uc`, `service/hot_reload.uc`, `limited_download_command`) that
  this fork does not have.
- **Storage planning for Sing-Box X / Extended Compressed** (`4ad9dd26`) is
  tied to upstream's core variants.
- Excluded on purpose: the subscription provider allowlist
  (`subscription/parser.uc`), remote support with the upstream operator's
  SSH key, and the Rust X / Sing-Box X / Tachyon feeds hosted on
  `mirror.51343.ru`.

## Signed releases

The mirror already signed its APK index with its own key, which routers trust
as `/etc/apk/keys/forkop-mirror.pem`. The packages themselves were unsigned.
`ops/mirror/publish-forkop-feed.sh` now signs every APK with the same key
before indexing it. It also writes `forkop-manifest.json`, `forkop-apk.pem`
and `SHA256SUMS` into `updates/releases/<version>/`. Like upstream, this does
not change client trust: routers still check SHA-256 and the existing
installer paths still pass `--allow-untrusted`.

Verified on the home mirror with a throwaway key and a temporary root, using
the 1.0.48 packages. All three APKs were signed and verified, the index
verified, and the catalog and `release.json` carried the signed hashes. A
second run reused the signed packages and left every hash unchanged. The
router's apk 3.0.5 verified a signed package against the test key.
