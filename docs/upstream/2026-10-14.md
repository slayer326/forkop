# Selective upstream audit: 2026-10-14

## Compared revisions

- Fork baseline: `7985766a` (release 1.0.49).
- Previous audit: [2026-10-12](2026-10-12.md), upstream `d3d1650d`.
- New upstream: [Screamshow/forkop-x](https://github.com/Screamshow/forkop-x)
  `2ac41616` (2.3.2, with the 2.3.3 notes prepared).

Nine upstream commits plus the items in the 2.3.2 notes that were not
covered last time. The histories are unrelated, so each fix was re-applied
by hand.

## Ported

**DNS kept during a restart** (`4c9a9d64`). `lifecycle.restart()` called
`stop_impl()`, which hands dnsmasq back to the upstream resolvers before
the new core starts. Clients that resolved in that window cached real
addresses and bypassed FakeIP until those entries expired. A restart now
stops only the runtime (`stop_main()`), like the reload path's
`restart_runtime_for_reload()`. dnsmasq configuration is idempotent, so
the next start leaves it pointed at sing-box. Every path that leaves
Forkop stopped still restores DNS: a failed stop or start goes through
`cleanup_failed_runtime()`. A manual restart abandoned because a user Stop
won the race (this fork's stop-sensitive path; upstream has no equivalent)
restores DNS through the new `dnsmasq_restore_for_stop()`, which
`stop_impl()` now uses as well. Upstream also routes `init.d restart`
through this path. Here `init.d restart` stays an explicit stop and start
with its stop-request markers, and LuCI's Restart already uses the
lifecycle path.

**No reload for an unchanged subscription** (`0b3979e3`). After a
subscription refresh, the configuration the new caches would produce is
generated into a stage and compared whole with the running one. If nothing
differs (servers, selectors, URLTest, DNS, routing), only the section cache
is published and the reload is skipped, so open connections survive. Unlike
upstream, a comparison that cannot be completed falls back to the ordinary
reload instead of failing the update. Covered by
`tests/subscription_runtime_unchanged.sh`.

**Subscription caches across upgrades** (User-Agent part of `cd4ef44f`).
The automatic User-Agent carries the sing-box version (`sing-box/<ver>`) or
the Forkop version (`Happ/<ver>`). After any core or package upgrade, the
saved cache no longer matched and was rejected. With the subscription
source unreachable, an offline start then had no servers. Any version of
these two automatic profiles is now accepted. An explicit User-Agent still
has to match exactly.

**Full-device routing in monitoring** (`7dfb8834`). A connection matched by
a section's "route all traffic of these devices" rule is shown as
"Весь трафик устройства · <address>" instead of the raw rule. Conditional,
inverted or truncated rules keep their raw text.

**Store references** (from `a8d5bb21`). `StoreService.set()` now keeps the
previous object for keys whose content did not change, so views that
compare by reference do not redraw.

**Stalled downloads** (2.3.2 notes). Component and rule-set downloads now
abort after 15 s below 1 byte/s, as subscription and update downloads
already did. A slow transfer continues while data arrives.

## Not ported

- **One guarded reload for list and section changes** (`e5ea5829`). This
  rebuilds upstream's list-apply transaction across `updates.uc`,
  `lifecycle.uc` and `state.uc` around their hot-reload design. Our list
  update path is structured differently; this needs its own design and
  router testing.
- **Cache relocation when sources are reordered** (rest of `cd4ef44f`).
  The sources' metadata sidecars and the migration before pruning are a
  separate, riskier change. Only the upgrade part above is taken.
- **Dashboard memory metrics and inline latency updates** (rest of
  `a8d5bb21`). They depend on backend fields (`singboxMemoryBytes`) this
  fork does not report.
- **Direct QUIC blocking** for "Отключить QUIC" (`0b602904`). It adds a
  `quic_forward` chain on the forward hook; it needs the same autotune
  contract review as the prerouting changes deferred on 2026-10-12.
- Rust X, its hot reload, the FakeIP cache split by core family and
  Tailscale support remain out of scope.
