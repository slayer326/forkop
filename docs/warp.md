# WARP через интерфейс OpenWrt

WARP подключается через отдельный WireGuard/AmneziaWG-интерфейс. Установленное ядро sing-box не заменяется. Мастер находится в секции с действием «Подключение», на вкладке «Куда», рядом с сетевыми интерфейсами.

## Настройка

1. Откройте «Импортировать или создать профиль WARP» и выберите WireGuard либо AmneziaWG.
2. Нажмите «Подготовить компоненты туннеля». Используются только настроенные репозитории роутера: APK или OPKG проверяет зависимости, включая совместимость модуля с ядром Linux, перед установкой. Принудительная установка и отключение проверки подписей не применяются.
3. Вставьте профиль формата `[Interface]` / `[Peer]` или примите условия Cloudflare и нажмите «Сгенерировать профиль WARP». Регистрация требует доступного API Cloudflare. При необходимости включите регистрацию через работающую секцию, выбранную в настройках скачивания списков.
4. Оставьте предложенное имя или введите до 10 латинских букв, цифр или знаков подчёркивания. Мастер добавит префикс `fkw` и переведёт имя в нижний регистр, например `WARPs` станет `fkwwarps`. Нажмите «Создать и добавить в секцию».
5. Закройте мастер, сохраните секцию и примените настройки Forkop. Проверьте рукопожатие после отправки трафика через секцию. Создание интерфейса само по себе не доказывает доступность WARP.

Несколько туннелей требуют отдельных профилей: один приватный ключ нельзя повторно устанавливать в несколько интерфейсов. Готовые интерфейсы можно использовать в существующих группах и приоритетах.

## Платформы

Модуль написан на ucode и shell и не содержит бинарников конкретной архитектуры. Общий путь используется для aarch64 (ARM64), ARMv7, MIPS/MIPSel, x86_64 и других поддерживаемых OpenWrt архитектур. Пакетные менеджеры OPKG (ветка 24.10) и APK (ветка 25.12) обслуживаются отдельно.

Наличие совместимого системного модуля остаётся обязательным:

- WireGuard: `wireguard-tools` и его зависимость `kmod-wireguard` из репозитория соответствующей прошивки.
- AmneziaWG: `amneziawg-tools` и `kmod-amneziawg`. Эти пакеты должны уже быть доступны в настроенном доверенном репозитории. Мастер не запускает сторонние установщики и не подменяет репозитории. Для сборки с иным kernel ABI установка будет отклонена.

Это поддержка общего программного пути, а не утверждение о проведённых испытаниях на каждой модели роутера. Нельзя обещать совместимость произвольных модулей с кастомными прошивками.

## Изоляция и восстановление

- Существующие интерфейсы не перезаписываются. Меняются только новая секция интерфейса и его peer в `/etc/config/network`.
- Для адресов интерфейса принимаются только host-префиксы `/32` и `/128`. IPv6 включается отдельно.
- DNS из профиля не применяется, автоматические маршруты `AllowedIPs` выключены. Профили с `PostUp`, `PreDown` и другими исполняемыми командами отклоняются.
- WireGuard/AWG использует метку обхода перехвата Forkop; адреса обоих типов туннелей также исключаются из nft-перехвата.
- Используется перечитывание конфигурации netifd, а не `service network restart`. При отказе применения возвращается исходный файл, если его не изменил другой процесс.
- Ключи передаются через stdin/RPC и временные файлы с правами `0600` в каталоге `0700`. Тело регистрации и временные копии удаляются после операции. Результат генерации удаляется после получения мастером; оставленные результаты ограничены сроком жизни и очищаются при последующих операциях.
- Сам профиль интерфейса хранится в `/etc/config/network`. Перед удалением интерфейса уберите его из секций Forkop и примените настройки, затем удалите только нужный интерфейс через «Сеть → Интерфейсы».

Обычный WireGuard и обфускация AWG не гарантируют доступность Cloudflare у конкретного оператора. Отказ регистрации не затрагивает рабочую сеть; можно импортировать готовый профиль.

## CLI

`forkop warp_status` показывает доступность компонентов. Для автоматизации `forkop warp_rpc start` читает JSON из stdin и возвращает `job_id`; `forkop warp_rpc job` принимает `{"id":"..."}`, а `forkop warp_rpc ack` удаляет завершённый результат. Не передавайте приватный профиль аргументом командной строки и не публикуйте результаты генерации.

Действия `start`: `prepare`, `generate`, `import`. Тип `kind`: `wireguard` или `amneziawg`. Для генерации требуется `accept_terms: true`; `via_proxy: true` использует действующий локальный прокси скачивания списков. Для импорта нужны `name`, `profile` и при необходимости `ipv6: true`.
