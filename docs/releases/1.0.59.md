## Forkop X 1.0.59 — ядро podkop-engine

- На вкладке «Компоненты» добавлены кнопки «Установить podkop-engine» и «Установить podkop-engine-full». [podkop-engine](https://github.com/podkop-net/podkop-engine) — сборка sing-box с исправлениями совместимости с Xray-core: REALITY для серверов Xray 26.7+, актуальные отпечатки uTLS, XHTTP, шифрование VLESS, экономия памяти, более устойчивые DoH и FakeIP.
- Ставится линия 1.14 из релизов podkop-net/podkop-engine на GitHub для архитектуры роутера. Пакет проверяется по `SHA256SUMS` релиза до остановки Forkop. При неудачной установке или запуске восстанавливается прежний вариант ядра, а для podkop-engine — ровно та версия, что стояла раньше.
- Обновление podkop-engine проверяется и устанавливается той же кнопкой, что и для других вариантов ядра.
- XHTTP с podkop-engine работает так же, как с sing-box-extended: поддержка определяется по строке `Features:` в `sing-box version`.

Что учесть перед переключением:

- `podkop-engine` (около 23 МБ на aarch64) не содержит VMess, AnyTLS, ShadowTLS и NaiveProxy. VMess есть в `podkop-engine-full` (около 35 МБ). Ни в одной из сборок нет Tailscale и DNS по DoQ.
- Если в конфигурации есть то, чего нет в выбранной сборке, проверка `sing-box check` не пройдёт и переключение откатится к прежнему ядру.
- Init-скрипт пакета по умолчанию скачивает 64 КиБ через сервер перед переключением группы urltest на него. Отключается командой `uci set sing-box.main.urltest_download_check=0; uci commit sing-box`. Служба `podkop-engine` (failsafe) ставится вместе с пакетом; её действия, связанные с podkop, без podkop не выполняются.
- Пакет скачивается с GitHub напрямую, или через прокси Forkop, если для компонентов включена загрузка через прокси. Через зеркало Forkop он не идёт.

Настройки маршрутизации, DNS и QUIC не меняются. При установке трёх пакетов Forkop X служба кратко перезапустится; ядро sing-box само не меняется, пока вы не нажмёте кнопку.
