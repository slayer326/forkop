## Forkop X 1.0.61 — сайты за Cloudflare идут через прокси, веб-версия Zapret-Manager, автоподбор стратегий выключен

### Сайты, найденные по списку адресов, больше не уходят напрямую

На sing-box 1.14 и podkop-engine домен, реальный адрес которого попадает в список адресов (например, список `cloudflare`), получает адрес FakeIP. Соединение доходит до маршрутизации уже только с именем домена, и список адресов, который его выбрал, не может с ним совпасть. Соединение уходило по последнему правилу — напрямую, а провайдер такие адреса Cloudflare блокирует. В журнале это выглядело так: `open connection to bt4.t-ru.org:80 using outbound/direct[direct-out]: … dial tcp 188.114.97.3:80: i/o timeout`.

Теперь перед первым правилом со списком адресов Forkop X заново определяет адрес такого домена (ответ берётся из кэша DNS), и правило совпадает. Правила по доменам по-прежнему проверяются раньше, а соединений к реальным адресам изменение не касается.

- Проверено на роутере: bt4.t-ru.org, lgrom.com и ipsw.pro без исправления уходили напрямую, с ним — через прокси секции.

### Zapret-Manager: веб-версия (из Forkop X 2.5.0)

- Установка Zapret-Manager на вкладке «Компоненты» теперь устанавливает и его веб-версию (LuCI: Службы → Zapret Manager) через зеркало Forkop — только если её нет или вышла более новая. Установка перезапускает `rpcd` и `uhttpd`.
- Команды `zms` и `zmw` (обновление веб-версии) работают через зеркало Forkop.
- Удаление убирает и веб-версию. Чужой `/usr/bin/zms*`, созданный не Forkop и не Zapret-Manager, не удаляется, и тогда удаление ничего не меняет.

### Автоподбор стратегий DPI выключен

- **Zapret-Manager.** Его автоподбор по расписанию перезапускал zapret со стратегиями по очереди и переписывал `NFQWS_OPT`, которым управляет Forkop. Forkop больше не устанавливает команду `zmsA` и удаляет задания автоподбора (`zmsA --auto-best` и `# zm-autobest`) при установке и при каждом запуске и перезагрузке настроек Forkop.
- **Автоподбор Forkop X.** Режим «Автоматически» убран: Forkop больше не меняет стратегию сам. Сохранённый режим «Автоматически» работает как «Только рекомендации» — проверки по расписанию продолжаются, а рекомендацию применяет администратор на странице автоподбора.

### TorrServer Direct и FakeIP (из Forkop X 2.5.0)

- Соединения TorrServer к адресам FakeIP (IPv4 и IPv6) теперь идут через ядро Forkop, а соединения с пирами по реальным адресам остаются прямыми. Раньше трекеры из списков уходили в WAN с адресом 198.18.x.x и не подключались.
- Старые правила TorrServer Direct без исключений FakeIP заменяются автоматически; при обновлении служба TorrServer Direct перезапускается.

Настройки маршрутизации и DNS не меняются. При обновлении Forkop X служба кратко перезапустится.
