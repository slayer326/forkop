## Роутеры с выключенным IPv6

- **Forkop X больше не отказывается стартовать там, где нет IPv6.** Если IPv6 выключен в ядре или на loopback, запуск прерывался на попытке создать IPv6-маршрут для TPROXY:

  ```
  [fatal] Failed to add IPv6 route for tproxy. Aborted.
  [fatal] Startup phase 'nft-rebuild' failed with exit status 1
  ```

  Дальше включался автоматический повтор, который падал там же, снося уже построенную IPv4-часть. Роутер оставался в бесконечном цикле перезапуска вообще без прокси — продукт не работал целиком из-за протокола, который на этом роутере не использовался.

  Теперь при недоступном IPv6 его маршрут и правило маркировки просто не создаются, а запуск продолжается. Трафик IPv4 обрабатывается как обычно.

- **Настоящая неисправность по-прежнему прерывает запуск.** Если ядро сообщает, что IPv6 доступен, но отказывается принять маршрут или правило, это ошибка, а не отсутствие протокола, и Forkop X останавливается, как и раньше.

### Проверка

Поломка воспроизведена на роутере netis NX31 с `disable_ipv6=1` для `all`, `default` и `lo`, и исправление проверено там же, на трёх сценариях: без IPv6 запуск проходит полностью, с IPv6 создаются обе половины, при заявленном но отказывающем IPv6 запуск прерывается.

Отдельно проверено, что правило маркировки IPv4 создаётся и при отсутствии IPv6: оно добавляется после IPv6-маршрута, и небрежная проверка оставила бы помеченные пакеты без маршрута.
