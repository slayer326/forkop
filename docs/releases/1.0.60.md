## Forkop X 1.0.60 — серверы с `fp=chrome` снова работают на podkop-engine, списки через прокси снова скачиваются

### Подключения с отпечатком `chrome` на podkop-engine

После перехода на podkop-engine подключения с `fp=chrome` у многих перестали работать. Причина не в сервере. Отпечаток `chrome` в podkop-engine отправляет ключ X25519MLKEM768, как клиент Xray, и ClientHello вырастает примерно до 1,8 КБ. Часть российских провайдеров замораживает такие ClientHello, когда к серверу открывается сразу много соединений. Обычный sing-box отправлял `chrome` без этого ключа, поэтому раньше всё работало.

Теперь Forkop X включает в podkop-engine автосмену отпечатка uTLS. Если сервер не ответил на ClientHello, ядро за секунду-другую пробует другой отпечаток и дальше использует тот, что сработал. Начиная с podkop-engine r17 первым пробуется `chrome` без ключа X25519MLKEM768 (как у обычного sing-box), затем `firefox`. Выбор запоминается для сервера на сутки.

- Проверено на роутере: сервер REALITY с `fp=chrome` через podkop-engine — 3 подключения из 10 без автосмены и 10 из 10 с ней.
- Работает только с podkop-engine r13 и новее. Forkop узнаёт об этой возможности из `sing-box version` и в другие ядра раздел не пишет.
- Рекомендуем обновить ядро до r17 кнопкой обновления на вкладке «Компоненты».
- Отключить автосмену: `uci set forkop.settings.utls_fallback=0; uci commit forkop`, затем перезапустить Forkop.

### Загрузка списков через прокси при запуске

Если была включена «Загрузка списков через прокси», после обновления Forkop мог не запуститься. Все загрузки списков подсетей (Discord, Meta, Twitter и других) сразу завершались ошибкой, хотя адреса были доступны.

Сохранённые списки хранятся под адресом, с которого их скачали, а адрес зеркала в проверку актуальности не входил. Если списки были скачаны с GitHub или с другого зеркала, при запуске Forkop не находил их у себя и шёл скачивать заново. Это происходило ещё до запуска sing-box, через прокси, который в этот момент не работает.

- Один и тот же список с зеркала Forkop, jsDelivr и GitHub теперь считается одним файлом, и сохранённая копия используется.
- Если сохранённой копии какого-то списка действительно нет, Forkop при запуске скачивает списки через временное подключение к выбранной секции, как при первом запуске.
- В журнале у каждой неудачной попытки загрузки теперь есть причина от curl. Например: `failed: curl: (7) Failed to connect to 127.0.0.1 port 4534 … (through the Forkop service proxy 127.0.0.1:4534)` или `failed: curl: (60) SSL certificate problem`.

Настройки маршрутизации и DNS не меняются. При обновлении Forkop X служба кратко перезапустится.
