# 1.0.15 validation

The candidate ports URLTest visibility, expandable Priority membership, subscription
Bootstrap DNS and latency-busy handling. It does not import upstream provider
restrictions, global exclusion defaults, DNS snapshot migration or release channels.

## Completed

- 61 ucode sources compiled in ordinary and strict modes: 122 checks passed.
- All 102 backend shell test files passed in a non-root, no-network Linux container
  using OpenWrt 24.10.5 ucode, with CPU/RAM/PID limits and a read-only input snapshot.
- All 509 frontend tests passed; formatting, ESLint, TypeScript and LuCI build passed.
- Eight no-network cache tests cover URL restrictions, redirects, private IPs,
  atomic downloads, file-size limits, eviction and the adapted manager default.
- The own mirror serves both manager entry URLs, GitHub latest-release metadata,
  a raw support file and Routerich 24.10/25.12 indexes with HTTP 200.
- A mirrored Zapret release archive matched upstream size and SHA-256.
- Requests for internal/unapproved hosts receive HTTP 403.
- Only the dedicated mirror web service and new cache container were restarted.
  Existing application, database and edge Caddy start times were unchanged.
- Previous web configuration is saved outside the public tree in the deployment
  audit directory, for rollback.

## Required before stable publication

Publication decision: after being informed that no physical-router test was
performed, the owner explicitly requested publication on 2026-09-11. The release
notes disclose that limitation. The hardware checklist below remains unverified.

No test-router target/access has been supplied yet. Automated tests are not a
substitute for these hardware checks:

1. Record OpenWrt version, architecture, available storage and installed package
   versions. Back up the current router configuration and keep previous packages.
2. Install the candidate on an explicitly designated test router only.
3. Verify a real HTTPS subscription from a non-upstream provider.
4. Verify URLTest member selection and Priority levels/current server/latencies.
5. Verify latency completion, concurrent-request errors and recovery after a
   terminated test worker.
6. Test Save & Apply, subscription/list refresh and reboot recovery. Confirm there
   is one managed sing-box instance and no loss of working routes or DNS.
7. Exercise package rollback if any check fails. Tag 1.0.15 only after success.

Do not install Zapret-Manager options unattended on production: it is a separate
third-party tool that can change router services and networking. Its optional
menus are not all tested or fully mirrored.
