## Forkop X 1.0.64 — podkop-engine-full поверх sing-box-tiny, маршрутизация после перезапуска сети, исправления из Forkop X 2.6.0

### podkop-engine-full устанавливается вместо sing-box-tiny

На OpenWrt 24.10 (opkg) установка podkop-engine-full на вкладке «Компоненты» при установленном sing-box-tiny заканчивалась ошибкой «Failed to install required sing-box dependencies; the current sing-box variant was kept». Перед заменой сборки Forkop X пробно устанавливает пакет (`opkg --noaction`), чтобы заранее доустановить его зависимости. podkop-engine-full объявляет конфликт с sing-box-tiny, а opkg проверяет конфликты раньше зависимостей, поэтому пробная установка всегда отказывала, хотя смена сборки сама удаляет sing-box-tiny.

Теперь, если пробная установка упирается только в другую сборку sing-box, Forkop X повторяет её без проверки конфликтов и доустанавливает найденные зависимости. Конфликт с любым другим пакетом и зависимость, которой нет в репозиториях, по-прежнему останавливают смену сборки до удаления текущей.

### Маршрутизация возвращается после перезапуска сети (из Forkop X 2.6.0)

После `/etc/init.d/network restart` netifd удаляет все правила `ip rule`, и пропадают маршруты таблицы forkop, а sing-box и таблица nftables продолжают работать: трафик секций никуда не доходил, а Forkop X показывался остановленным. Теперь при подъёме WAN Forkop X возвращает правило и маршруты, не перезапуская ядро. Применение настроек сети в LuCI сеть не перезапускает, и его это не касалось.

### Ответные пакеты не перехватываются (из Forkop X 2.6.0)

Обе цепочки перехвата проводили пакеты ответного направления через правила секций. Ответы на входящие соединения к устройствам в LAN (например, по IPv6 к полностью маршрутизируемому устройству) и ответы служб роутера через WAN могли попасть в TPROXY, и такие соединения обрывались. Теперь ответные пакеты покидают цепочки сразу; заодно загрузки меньше нагружают процессор правилами.

### Время роутера после отключения питания (из Forkop X 2.6.0)

Роутер без часов реального времени после отключения питания загружается с устаревшим временем. При DNS через HTTPS или TLS сертификат DNS-сервера считался ещё не действительным, имена NTP-серверов не разрешались, и время так и не устанавливалось. Теперь имена серверов из настроек системы (Система → Синхронизация времени) разрешаются через bootstrap DNS, которому часы не нужны. Серверы, заданные адресом, и выключенная синхронизация ничего не меняют.

### Обновление Forkop X не откатывается из-за занятого opkg (из Forkop X 2.6.0)

После установки новой версии Forkop X проверяет версии установленных пакетов. Если opkg в этот момент был занят другим процессом или apk завершался ошибкой без сообщения, версия читалась как пустая, и успешное обновление откатывалось. Теперь запрос повторяется, при неудаче версия читается из базы пакетов напрямую, а откат выполняется только при действительно прочитанной другой версии. В журнале указываются ожидаемая и найденная версии.

### Проверка задержки списка прокси быстрее (из Forkop X 2.6.0)

Проверка задержки на дашборде опрашивала прокси по одному и для каждого ждала свой таймаут: список из десятков прокси проверялся минутами, и всё это время другие проверки отклонялись. Теперь прокси проверяются группами по четыре, а группы URLTest — после своих участников, как раньше.

Настройки не меняются. При обновлении Forkop X служба кратко перезапустится.
